The editor above is **real**: it runs on this page, and everything you type
shows up as Markdown on the right. Select a word, type `/`, press `Ctrl+B` —
whatever you'd do in Word.

## Why Kalem?

Markdown has become the de facto output format of AI tools. But there is no
Markdown editor that people who don't write code can use as comfortably as
Word: either they're handed raw text, or an editor that stores JSON and
"converts" it to Markdown — and that conversion is lossy.

<CardGrid stagger>
  <Card title="Markdown-native" icon="pencil">
    The source of truth is always Markdown text, not JSON. A line the user
    didn't touch comes back byte-for-byte — a list you wrote with `*` doesn't
    come back as `-`.
  </Card>
  <Card title="Framework-agnostic" icon="puzzle">
    The core is plain TypeScript. `@kalem-editor/react` and `@kalem-editor/vue` are
    separate packages that take the framework as a `peerDependency`. Svelte,
    Angular and plain HTML don't even need a wrapper: `<kalem-editor>` is the
    browser's own component model.
  </Card>
  <Card title="Small" icon="rocket">
    The badges above are measured values (min+gzip), not targets. Budgets
    are enforced in CI; going over means a red build.
  </Card>
  <Card title="Modular" icon="setting">
    `@kalem-editor/viewer` just to display; `@kalem-editor/editor` to edit; `@kalem-editor/ui`
    for the Word-like interface. You don't download what you don't use.
  </Card>
</CardGrid>

## In five lines

<Tabs syncKey="cerceve">
  <TabItem label="Vanilla">

```ts
import { Editor } from '@kalem-editor/editor';
import { mountUi } from '@kalem-editor/ui';

const editor = new Editor(document.getElementById('app')!, {
  value: '# Hello',
  lang: 'en',
  label: 'Document',
  onChange: (markdown) => console.log(markdown),
});
mountUi(editor);
```

  </TabItem>
  <TabItem label="React">

```tsx
import { KalemEditor } from '@kalem-editor/react';
import { mountUi } from '@kalem-editor/ui';

<KalemEditor
  defaultValue="# Hello"
  lang="en"
  label="Document"
  onChange={(markdown) => console.log(markdown)}
  onReady={(editor) => mountUi(editor)}
/>
```

  </TabItem>
  <TabItem label="Vue">

```vue
<script setup lang="ts">
import { KalemEditor } from '@kalem-editor/vue';
import { mountUi } from '@kalem-editor/ui';
import { ref } from 'vue';
const text = ref('# Hello');
</script>

<template>
  <KalemEditor v-model="text" lang="en" label="Document" @ready="mountUi" />
</template>
```

  </TabItem>
  <TabItem label="HTML">

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@kalem-editor/themes/css/tokens.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@kalem-editor/themes/css/viewer.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@kalem-editor/themes/css/editor.css">

<kalem-editor label="Document"># Hello</kalem-editor>

<script src="https://cdn.jsdelivr.net/npm/@kalem-editor/wc/dist/kalem-editor.iife.js"></script>
```

  </TabItem>
</Tabs>

All four tabs set up the same editor. The last one has no build step, no
bundler and no JavaScript written by you.

## Comparison

| | Kalem | Tiptap | BlockNote | Editor.js |
|---|---|---|---|---|
| Markdown first-class | ✅ | ❌ HTML-focused | ❌ JSON | ❌ JSON |
| Framework-agnostic | ✅ | ✅ | ❌ React required | ✅ |
| Runtime dependencies | **0** | ~10 packages | ~15 packages | a few |
| Editor + UI (min+gzip) | **38.0 kB** | ~90–120 kB | ~150 kB+ | ~30 kB + plugins |
| Drag-and-drop blocks | ✅ | Extension | ✅ | ✅ |
| Lossless round-trip | ✅ | Partial | ❌ | ❌ |

<Aside>
Kalem's number is measured by `size-limit` and re-checked on every CI run.
The competitors' values are approximate (min+gzip) and were not measured
independently.
</Aside>
