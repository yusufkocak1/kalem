asterisk list doesn't turn into `-`, and the `1)` delimiter doesn't become `1.`.

## This page is the proof of a claim

Kalem's main claim is framework independence. A library can say that;
proving it is another matter.

This site is built with [Astro Starlight](https://starlight.astro.build) and
runs **both React and Vue islands** at the same time. The three editors above
live on one page, on one `@kalem-editor/editor` engine.

This page couldn't have been written with Vue-based VitePress or React-based
Docusaurus — the choice of documentation tool is part of the message.

<Aside type="tip" title="Things to try">
- **Select** a word — the formatting bubble appears
- Type `/` on an empty line — the block menu opens
- Type `# ` or `- ` — the line turns into a heading or a list on its own
- `Ctrl+B`, `Ctrl+I`, `Ctrl+K` — the keys you know from Word
- Drag the block handle, or move a block with `Ctrl+Shift+↑/↓`
</Aside>

## The Vue example is rendered on the server

The React and Vue islands are set up with `client:load`, which means they're
**rendered on the server first**. The Vue tab shows a visible result of this:
look at the page source and the document's `<h1>` and list are there — before
any JavaScript loads.

The "you don't need `<ClientOnly>`" claim on the [Nuxt page](/en/frameworkler/nuxt/)
is right there in this page's own HTML.

## All three open with the same document

The starting text lives in a single module and all three import it. That way
the only difference is the mounting code: same input, same output, three
different frameworks.
